# Getting Started

Mystic Programming Language (MPL) is used to create scripts, utilities, menu-driven tools, and other extensions for Mystic BBS.

This guide introduces the documentation structure and the basic workflow used when developing an MPL program. It does not assume previous experience with MPL, but familiarity with basic programming concepts will be helpful.

> **Documentation status**
>
> This project is under active development. Examples and language behavior should be verified against the Mystic BBS version being used.

## What You Will Learn

After completing the beginner documentation, you should understand how to:

- Identify MPL source and compiled program files
- Create a basic MPL source file
- Compile an MPL program
- Run the compiled program from Mystic BBS
- Recognize common compiler and runtime problems
- Find the appropriate language-reference page

## Before You Begin

You will need:

- A working Mystic BBS installation
- Access to the Mystic installation directories
- Permission to create and modify MPL source files
- Access to the MPL compiler included with Mystic
- A text editor that preserves plain-text source files

A terminal-based editor, graphical editor, or development editor can be used. The important requirement is that the file remains plain text.

## MPL Files

MPL development generally involves two file types:

| File type | Purpose |
|---|---|
| `.mps` | MPL source code written and edited by the developer |
| `.mpx` | Compiled MPL program executed by Mystic BBS |

The source file is the file you maintain. The compiled file is generated by the MPL compiler.

Do not edit an `.mpx` file directly.

## Basic Development Workflow

A typical MPL workflow is:

1. Create or edit an `.mps` source file.
2. Compile the source file with the MPL compiler.
3. Review and correct any compiler errors.
4. Place or retain the resulting `.mpx` file where Mystic can access it.
5. Run the program from a Mystic menu command or another supported entry point.
6. Test the program in a controlled environment.
7. Repeat the process after each source change.

## Recommended Project Organization

Keep source files separate from generated files whenever practical.

A simple development layout might be:

```text
mpl-project/
├── source/
│   └── hello.mps
├── include/
├── build/
│   └── hello.mpx
└── notes/
```

The exact location used by Mystic depends on the local installation and configuration. Document the directories used by your system so that source files and compiled files are not confused.

## MPL Program Structure

An MPL source file can be a small statement-only script or a larger structured program containing declarations, procedures, functions, and a main executable block.

A minimal script can be as small as:

```pascal
WriteLn('Hello from Mystic MPL!');
WriteLn('|PA');
```

A larger program may use a Pascal-style structure:

```pascal
Var
  UserName : String = 'Mystic User';

Procedure ShowGreeting;
Begin
  WriteLn('Hello, ' + UserName);
End;

Begin
  ShowGreeting;
End.
```

This example demonstrates:

- A `Var` section for program-level data
- A procedure declared before executable code
- A final `Begin` / `End` block containing the main program flow
- Semicolon-terminated statements and declarations

Traditional Pascal often begins with a declaration such as `Program HelloWorld;`. Mystic's current MPL examples generally begin directly with declarations or executable statements, so this documentation does **not** treat a `Program Name;` header as required MPL syntax.

See [Program Structure](Program-Structure) for declaration order, scope, blocks, routines, minimal scripts, and compiler-specific structure notes.

## Testing Recommendations

Use a test system or a restricted test account while developing MPL programs.

Before deploying a new program:

- Confirm that the source compiles without errors.
- Test every menu path and user-input path.
- Test invalid and unexpected input.
- Confirm that files are opened using the intended paths.
- Verify behavior with a non-administrator BBS account.
- Back up existing scripts and compiled programs before replacing them.
- Record the Mystic version used during testing.

## Troubleshooting Checklist

When an MPL program does not compile or run, check the following:

- The source filename uses the expected `.mps` extension.
- The compiler is being run from the correct location.
- Required include files can be found.
- Statements use the required terminators.
- `Begin` and `End` blocks are balanced.
- String delimiters are paired correctly.
- The compiled `.mpx` file was created.
- Mystic is referencing the correct compiled file.
- Filename capitalization matches on case-sensitive operating systems.
- The current Mystic version supports the documented feature.

See [Troubleshooting](Troubleshooting) for expanded diagnostic guidance.
